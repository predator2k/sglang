================================================================
Root cause (definitively identified via debug logging)
================================================================
NGRAM's tree-attention protocol writes draft tokens at positions
[seq_lens, seq_lens+dn-1] with position encoding applied at those
positions. The CUDA tree-attention kernel self-masks the root (so
its logits = baseline-equivalent next-token prediction conditioned
only on PRIOR context).

tt-metal's decode_forward does standard causal self-attention with no
tree mask — every position attends to itself. To bypass this, our
T1.2 v4 fix ignores the drafts and decodes with input = prev_emit
(cached from prior cycle's argmax) at position = seq_lens. SGLang's
move_kv_cache then relocates this slot to the bonus position.

Critical implementation detail: prev_emit IS NOT in forward_batch
(input_ids contains NGRAM's predictions, not prev emits). We cache
prev_emit logits via self._last_emit_logits, updated in:
- _call_standard_forward (extend mode): captures prefill's last-
  position logits for use in cycle 1.
- _call_prefill_for_verify: captures this cycle's logits for cycle N+1.

Baseline's decode at the equivalent scheduler step uses position
seq_lens-1 (= position of the slot that's pre-allocated for the prev
emit). My fix uses position seq_lens because that's the slot SGLang
allocates in spec mode. The +1 rotary-encoding offset propagates
through attention as a subtle numerical drift; over many cycles, it
can flip an argmax at near-tie positions, causing the 11/100 divergence.

================================================================
Path to 100/100
================================================================
True bit-exactness requires tree-attention with self-masking at the
root position. tt-metal's `decode_forward` does standard causal
self-attention (every position attends to itself), so the input
token at position seq_lens leaks into the output logits — exactly
what CUDA's tree-mask suppresses.

Verified empirically (debug probe 2026-05-13):
  - SGLang DOES allocate kv slots at BOTH positions seq_lens-1 AND
    seq_lens in spec mode (slot_at_seq_lens_minus_1 = 70,
    slot_at_seq_lens = 71 for the first verify cycle).
  - The earlier hypothesis "kv hole at seq_lens-1" was wrong.
  - A dual-write fix (decode prev_emit at BOTH seq_lens-1 and
    seq_lens) was tried and gave 0/10: it double-counts prev_emit
    in the model's attention context, causing repetition outputs
    ("Paris, of course, Paris is not..." / "70 years ago ago,").

Real fix options (all out of P3a.1 scope per "no SGLang core changes"
user constraint):
  (a) Add tree-attention/self-mask support to tt-metal's decode_forward
      kernel. Closes the gap structurally.
  (b) Mathematically subtract self-attention contribution from output
      logits post-decode. Approximate; needs careful derivation.
  (c) Patch SGLang's NgramVerifyInput.prepare_for_verify protocol —
      explicitly disallowed by the user.
