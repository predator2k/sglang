================================================================
Crash signature: NGRAM verify shape mismatch (DESIGN GAP)
================================================================
After all the above patches land and the SGLang server boots through
tt_transformers warmup successfully, the first speculative-verify batch
crashes with:

  File "/sglang/python/sglang/srt/speculative/ngram_info.py", line 292
      target_predict = target_predict.reshape(bs, self.draft_token_num)
  RuntimeError: shape '[1, 12]' is invalid for input of size 1

Root cause: `TenstorrentLlamaForCausalLM._call_prefill_for_verify`
(models/tt_llm.py:226) currently returns `LogitsProcessorOutput(
next_token_logits=logits.squeeze(1))` where `logits` has shape `[bs, 1,
vocab]` — i.e. one logit row per request (the last-token-only output
that tt_transformers `prefill_forward` produces). NGRAM verify expects
`[bs * draft_token_num, vocab]` — one logit row per *draft token*.

This is a real implementation gap in the plugin path's verify flow that
the P3a.1 T1.2 SpecDecodeAdapter skeleton sketched but did not fully
implement.

================================================================
What's needed for proper NGRAM verify on tt_transformers
================================================================
`_call_prefill_for_verify` must return per-draft-position logits. The
options:

A. **Use Generator.prefill_forward_single_user_text directly**, pass
   `get_last_token_idx = (draft_seq_len - 1)` (snapped to the last
   32-token block boundary, which already covers the full 12 draft
   tokens since 12 ≤ 32). The kernel returns a 32-token-block of
   logits; we slice positions `[0, draft_seq_len)` from it and stack
   into `[bs, draft_token_num, vocab]`.

B. **Call decode_forward 12 times sequentially per draft.** Simpler
   API but ~12× slower than option A.

C. **A custom forward branch in tt_transformers** that returns
   per-position logits. Cleaner but requires upstream changes.

Option A is the right design target for P3a.1 T1.2 v2.
