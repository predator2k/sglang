The ForwardBatch.spec_info field carries an optional SpecInput (NgramVerifyInput,
EagleDraftInput, etc.) that encodes the draft tree structure, custom masks,
retrieve indices, and positional offsets required by the verifier. The plugin's
current forward() only branches on ForwardMode.EXTEND / ForwardMode.DECODE; a
TARGET_VERIFY batch arrives with forward_mode=TARGET_VERIFY (set in
ngram_worker.py:247) and a populated spec_info.

The TT model runner's forward() does not inspect spec_info at all today. Because
tt_transformers runs standard autoregressive attention, a TARGET_VERIFY batch with
a flat draft-token sequence and modified positions will be forwarded correctly only
if the attention mask is compatible with the verify tree structure. This requires
either (a) the verify batch to be collapsed to a flat sequence before dispatch
(handled by the spec runner before calling forward()) or (b) an explicit
SpecDecodeAdapter branch in the plugin.

Q3 answer: YES — verify-batch carries draft-tree shape via spec_info. Plugin's
current TTModels.forward() only handles EXTEND/DECODE; a new branch is needed.
This will be introduced as SpecDecodeAdapter in T1.1. The adapter must:
  1. Detect forward_mode == TARGET_VERIFY
  2. Flatten draft tree tokens and positions into the sequence format tt_transformers
     expects (one flat KV extension per verify step)
  3. Post-process logits to restore per-draft-token shape for spec_utils.py acceptance
